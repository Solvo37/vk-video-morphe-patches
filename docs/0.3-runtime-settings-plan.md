# 0.3 Stability / Runtime Settings plan

This branch is development-only. It must not publish stable APK releases.

## Runtime settings architecture

The goal is one patched APK with user-selectable behavior stored in SharedPreferences.

### Always-on compatibility fixes

These are not exposed as switches:

- stock VK coexistence fix;
- native signature check bypass;
- release signing / package compatibility.

Disabling any of these can make the app uninstallable or crash at startup.

### User-facing switches

Initial target:

- Show Clips tab: default ON
- Clips autoplay: default ON
- Pause Clips on open: default OFF
- Normal video autoplay: default ON
- Autoplay next video: default ON
- Hide promotional/ad UI: default ON
- Debug logging: default OFF

### Debug screen

Development screen should show:

- VK Video versionName/versionCode;
- patch bundle version;
- runtime flag values;
- reset runtime settings;
- diagnostic copy/export action later.

### Safety rules

- No runtime switch may change package/signing compatibility.
- Runtime hooks should fail open to stock behavior if a preference cannot be read.
- Changes to patch Kotlin code must not auto-publish a stable APK.
- Development artifacts remain GitHub Actions artifacts until real-device testing passes.

## Implementation phases

1. Add extension/runtime settings storage and a minimal settings Activity.
2. Add a safe entry point into the screen.
3. Connect one harmless switch first (debug logging).
4. Connect Clips visibility.
5. Connect Clips autoplay.
6. Connect normal video autoplay / next-video autoplay.
7. Add diagnostics and reset.
8. Only after real-device testing decide what is suitable for main.
